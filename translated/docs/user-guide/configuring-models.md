На этой странице
Hermes использует два вида слотов для моделей:
  * **Основная модель (Main model)** — модель, с помощью которой агент думает. Каждое сообщение пользователя, каждый цикл вызова инструментов и каждый потоковый ответ проходят через эту модель.
  * **Вспомогательные модели (Auxiliary models)** — небольшие фоновые задачи, которые агент делегирует. Сжатие контекста, зрение (анализ изображений), суммаризация веб-страниц, поиск по сессиям, оценка одобрения, маршрутизация MCP-инструментов, генерация названий сессий и поиск навыков. Каждая задача имеет собственный слот и может быть переопределена независимо.

На этой странице описана настройка обоих типов моделей через панель управления. Если вы предпочитаете конфигурационные файлы или CLI, перейдите к разделу [Альтернативные методы](#alternative-methods) внизу.
## Страница Models (Модели)[​](<#the-models-page> "Прямая ссылка на страницу Models")
Откройте панель управления и нажмите **Models** (Модели) на боковой панели. Вы увидите два раздела:
  1. **Model Settings (Настройки моделей)** — верхняя панель, где вы назначаете модели слотам.
  2. **Usage analytics (Аналитика использования)** — карточки с рейтингом, показывающие каждую модель, которая использовалась в сессиях за выбранный период, с количеством токенов, стоимостью и значками возможностей.

Обзор страницы Models
Верхняя карточка — это панель **Model Settings (Настройки моделей)**. Основная строка всегда показывает, какую модель агент будет использовать для новых сессий. Нажмите **Change** (Изменить), чтобы открыть выбор.
## Настройка основной модели[​](<#setting-the-main-model> "Прямая ссылка на Настройка основной модели")
Нажмите **Change** (Изменить) на строке Main model (Основная модель):
Диалог выбора модели
В окне выбора две колонки:
  * **Слева** — аутентифицированные провайдеры. Здесь отображаются только те провайдеры, которые вы настроили (указали API-ключ, прошли OAuth или определили собственную конечную точку). Если провайдера нет, перейдите в раздел **Keys** (Ключи) и добавьте его учётные данные.
  * **Справа** — курируемый список моделей для выбранного провайдера. Это агентные модели, которые Hermes рекомендует для данного провайдера, а не полный дамп `/models` (который на OpenRouter включает более 400 моделей, включая TTS, генераторы изображений и реранкеры).

Введите текст в поле фильтра, чтобы сузить поиск по имени провайдера, слагу или ID модели.
Выберите модель, нажмите **Switch** (Переключить), и Hermes запишет её в `~/.hermes/config.yaml` в раздел `model`. **Это применяется только к новым сессиям** — любые уже открытые вкладки чата продолжат использовать ту модель, с которой были запущены. Чтобы горячо заменить модель в текущем чате, используйте внутри него слеш-команду `/model`.
## Настройка вспомогательных моделей[​](<#setting-auxiliary-models> "Прямая ссылка на Настройка вспомогательных моделей")
Нажмите **Show auxiliary** (Показать вспомогательные), чтобы раскрыть восемь слотов задач:
Панель вспомогательных моделей (расширена)
Каждая вспомогательная задача по умолчанию имеет значение `auto` — это означает, что Hermes использует вашу основную модель и для этой задачи. Переопределите конкретную задачу, когда вам нужна более дешёвая или быстрая модель для фоновой работы.
### Распространённые сценарии переопределения[​](<#common-override-patterns> "Прямая ссылка на Распространённые сценарии переопределения")
Задача| Когда переопределять  
|---|---  
**Title Gen (Генерация названий)**|  Почти всегда. Flash-модель за $0.10/M пишет названия сессий так же хорошо, как Opus. В конфигурации по умолчанию для этой задачи установлена `google/gemini-3-flash-preview` на OpenRouter.  
**Vision (Зрение)**|  Когда ваша основная модель — это модель для кодирования без поддержки зрения (например, Kimi, DeepSeek). Укажите `google/gemini-2.5-flash` или `gpt-4o-mini`.  
**Compression (Сжатие)**|  Когда вы тратите токены рассуждения на Opus/M2.7 только для суммаризации контекста. Быстрая чат-модель справится с этой задачей в 50 раз дешевле.  
**Session Search (Поиск по сессиям)**|  Когда запросы поиска разветвляются — максимальное значение concurrency по умолчанию равно 3. Дешёвая модель делает расходы предсказуемыми.  
**Approval (Одобрение)**|  Для `approval_mode: smart` — быстрая/дешёвая модель (haiku, flash, gpt-5-mini) решает, стоит ли автоматически одобрять команды с низким уровнем риска. Дорогие модели здесь — пустая трата.  
**Web Extract (Извлечение с веб-страниц)**|  Когда вы активно используете `web_extract`. Та же логика, что и для сжатия — суммаризация не требует рассуждений.  
**Skills Hub (Центр навыков)**|  `hermes skills search` использует это. Обычно достаточно значения `auto`.  
**MCP**|  Маршрутизация MCP-инструментов. Обычно достаточно значения `auto`.  
### Переопределение для конкретной задачи[​](<#per-task-override> "Прямая ссылка на Переопределение для конкретной задачи")
Нажмите **Change** (Изменить) на любой строке вспомогательной задачи. Откроется тот же самый выбор — выберите провайдера и модель, нажмите Switch. Строка обновится, показывая `провайдер · модель` вместо `auto (use main model)`.
### Сброс всех на auto[​](<#reset-all-to-auto> "Прямая ссылка на Сброс всех на auto")
Если вы перенастроили параметры и хотите начать заново, нажмите **Reset all to auto** (Сбросить всё на auto) в верхней части раздела вспомогательных моделей. Все слоты вернутся к использованию вашей основной модели.
## Быстрая настройка через "Use as"[​](<#the-use-as-shortcut> "Прямая ссылка на Быстрая настройка через \"Use as\"")
У каждой карточки модели на странице есть выпадающее меню **Use as** (Использовать как). Это быстрый путь — выберите модель из аналитики, нажмите **Use as** и назначьте её на основной слот или любую конкретную вспомогательную задачу одним кликом:
Меню Use as
В выпадающем меню есть:
  * **Main model (Основная модель)** — то же самое, что нажать Change на основной строке.
  * **All auxiliary tasks (Все вспомогательные задачи)** — назначает эту модель сразу всем 8 вспомогательным слотам. Полезно, когда вы хотите, чтобы все фоновые задачи использовали дешёвую flash-модель.
  * **Индивидуальные задачи** — Vision (Зрение), Web Extract (Извлечение с веб-страниц), Compression (Сжатие) и т.д. Текущая назначенная модель для каждой задачи отмечена как `current`.

Карточки помечены значками `main` или `aux · <задача>`, если они в данный момент назначены какому-либо слоту — так вы с одного взгляда видите, какие из ваших исторических моделей и где используются.
## Что записывается в `config.yaml`[​](<#what-gets-written-to-configyaml> "Прямая ссылка на Что записывается в config.yaml")
Когда вы сохраняете настройки через панель управления, Hermes записывает в `~/.hermes/config.yaml`:
**Основная модель:**
[code] 
    model:  
      provider: openrouter  
      default: anthropic/claude-opus-4.7  
      base_url: ''        # очищается при смене провайдера  
      api_mode: chat_completions  
    
[/code]
**Переопределение вспомогательной (пример — vision на gemini-flash):**
[code] 
    auxiliary:  
      vision:  
        provider: openrouter  
        model: google/gemini-2.5-flash  
        base_url: ''  
        api_key: ''  
        timeout: 120  
        extra_body: {}  
        download_timeout: 30  
    
[/code]
**Вспомогательная на auto (по умолчанию):**
[code] 
    auxiliary:  
      compression:  
        provider: auto  
        model: ''  
        base_url: ''  
        # ... остальные поля без изменений  
    
[/code]
`provider: auto` с `model: ''` указывает Hermes использовать основную модель для этой задачи.
## Когда изменения вступают в силу?[​](<#when-does-it-take-effect> "Прямая ссылка на Когда изменения вступают в силу?")
  * **CLI** (`hermes chat`): при следующем запуске `hermes chat`.
  * **Gateway (Шлюз)** (Telegram, Discord, Slack и т.д.): при следующей _новой_ сессии. Существующие сессии сохраняют свою модель. Перезапустите шлюз (`hermes gateway restart`), если хотите принудительно применить изменения ко всем сессиям.
  * **Вкладка чата на панели управления** (`/chat`): при следующем новом PTY. Текущий открытый чат сохраняет свою модель — используйте внутри него `/model` для горячей замены.

Изменения никогда не инвалидируют кеши промптов в запущенных сессиях. Это сделано намеренно: замена основной модели внутри сессии требует сброса кеша (системный промпт содержит контент, специфичный для модели), и мы оставляем это для явной слеш-команды `/model` внутри чата.
## Устранение неполадок[​](<#troubleshooting> "Прямая ссылка на Устранение неполадок")
### В окне выбора нет "аутентифицированных провайдеров"[​](<#no-authenticated-providers-in-the-picker> "Прямая ссылка на В окне выбора нет \"аутентифицированных провайдеров\"")
Hermes отображает провайдера только при наличии действующих учётных данных. Проверьте раздел **Keys** (Ключи) на боковой панели — там должен быть указан API-ключ, пройдена OAuth-аутентификация или указан URL собственной конечной точки. Если нужного провайдера там нет, выполните `hermes setup` для его настройки или перейдите в **Keys** и добавьте переменную окружения.
### Основная модель не изменилась в запущенном чате[​](<#main-model-didnt-change-in-my-running-chat> "Прямая ссылка на Основная модель не изменилась в запущенном чате")
Ожидаемое поведение. Панель управления записывает `config.yaml`, который читают новые сессии. Текущий открытый чат — это активный процесс агента, который сохраняет модель, с которой был запущен. Используйте `/model <имя>` внутри чата для горячей замены модели в этой конкретной сессии.
### Переопределение вспомогательной модели "не вступило в силу"[​](<#auxiliary-override-didnt-take-effect> "Прямая ссылка на Переопределение вспомогательной модели \"не вступило в силу\"")
Проверьте три момента:
  1. **Вы начали новую сессию?** Существующие чаты не перечитывают конфиг.
  2. **Установлен ли `provider` в значение, отличное от `auto`?** Если в поле указано `auto`, задача всё ещё использует вашу основную модель. Нажмите **Change** (Изменить) и выберите реального провайдера.
  3. **Аутентифицирован ли провайдер?** Если вы назначили задаче `minimax`, но у вас нет API-ключа MiniMax, эта задача вернётся к провайдеру openrouter по умолчанию и запишет предупреждение в `agent.log`.

### Я выбрал модель, но Hermes сменил провайдера[​](<#i-picked-a-model-but-hermes-switched-providers-on-me> "Прямая ссылка на Я выбрал модель, но Hermes сменил провайдера")
На OpenRouter (или любом агрегаторе) простые имена моделей сначала разрешаются _внутри_ агрегатора. Поэтому `claude-sonnet-4` на OpenRouter становится `anthropic/claude-sonnet-4.6`, оставаясь в аутентификации OpenRouter. Но если бы вы ввели `claude-sonnet-4` в нативной аутентификации Anthropic, она осталась бы `claude-sonnet-4-6`. Если вы видите неожиданную смену провайдера, проверьте, что ваш текущий провайдер соответствует ожидаемому — окно выбора всегда показывает текущую основную модель в верхней части диалога.
## Альтернативные методы[​](<#alternative-methods> "Прямая ссылка на Альтернативные методы")
### Слеш-команда CLI[​](<#cli-slash-command> "Прямая ссылка на Слеш-команда CLI")
Внутри любой сессии `hermes chat`:
[code] 
    /model gpt-5.4 --provider openrouter             # только для сессии  
    /model gpt-5.4 --provider openrouter --global    # также сохраняется в config.yaml  
    
[/code]
`--global` делает то же самое, что кнопка **Change** (Изменить) на панели управления, плюс переключает текущую запущенную сессию на месте.
### Пользовательские псевдонимы[​](<#custom-aliases> "Прямая ссылка на Пользовательские псевдонимы")
Определите собственные короткие имена для часто используемых моделей, а затем используйте `/model <псевдоним>` в CLI или любой платформе обмена сообщениями:
[code] 
    # ~/.hermes/config.yaml  
    model_aliases:  
      fav:  
        model: claude-sonnet-4.6  
        provider: anthropic  
      grok:  
        model: grok-4  
        provider: x-ai  
    
[/code]
Или из командной строки (краткая форма `provider/model`):
[code] 
    hermes config set model.aliases.fav anthropic/claude-opus-4.6  
    hermes config set model.aliases.grok x-ai/grok-4  
    
[/code]
Затем используйте `/model fav` или `/model grok` в чате. Пользовательские псевдонимы переопределяют встроенные короткие имена (`sonnet`, `kimi`, `opus` и т.д.). Полную справку см. в разделе [Пользовательские псевдонимы моделей](</docs/reference/slash-commands#custom-model-aliases>).
### Подкоманда `hermes model`[​](<#hermes-model-subcommand> "Прямая ссылка на Подкоманда hermes model")
[code] 
    hermes model list                   # список аутентифицированных провайдеров и моделей  
    hermes model set anthropic/claude-opus-4.7 --provider openrouter  
    
[/code]
### Прямое редактирование конфигурации[​](<#direct-config-edit> "Прямая ссылка на Прямое редактирование конфигурации")
Отредактируйте `~/.hermes/config.yaml` и перезапустите всё, что его читает. Полную схему см. в [Справочнике по конфигурации](</docs/user-guide/configuration>).
### REST API[​](<#rest-api> "Прямая ссылка на REST API")
Панель управления использует три конечные точки. Полезно для автоматизации:
[code] 
    # Список аутентифицированных провайдеров + курируемые списки моделей  
    curl -H "X-Hermes-Session-Token: $TOKEN" http://localhost:PORT/api/model/options  
      
    # Чтение текущих назначений основной и вспомогательных моделей  
    curl -H "X-Hermes-Session-Token: $TOKEN" http://localhost:PORT/api/model/auxiliary  
      
    # Установка основной модели  
    curl -X POST -H "Content-Type: application/json" -H "X-Hermes-Session-Token: $TOKEN" \  
      -d '{"scope":"main","provider":"openrouter","model":"anthropic/claude-opus-4.7"}' \  
      http://localhost:PORT/api/model/set  
      
    # Переопределение одной вспомогательной задачи  
    curl -X POST -H "Content-Type: application/json" -H "X-Hermes-Session-Token: $TOKEN" \  
      -d '{"scope":"auxiliary","task":"vision","provider":"openrouter","model":"google/gemini-2.5-flash"}' \  
      http://localhost:PORT/api/model/set  
      
    # Назначение одной модели всем вспомогательным задачам  
    curl -X POST -H "Content-Type: application/json" -H "X-Hermes-Session-Token: $TOKEN" \  
      -d '{"scope":"auxiliary","task":"","provider":"openrouter","model":"google/gemini-2.5-flash"}' \  
      http://localhost:PORT/api/model/set  
      
    # Сброс всех вспомогательных задач на auto  
    curl -X POST -H "Content-Type: application/json" -H "X-Hermes-Session-Token: $TOKEN" \  
      -d '{"scope":"auxiliary","task":"__reset__","provider":"","model":""}' \  
      http://localhost:PORT/api/model/set  
    
[/code]
Токен сессии внедряется в HTML панели управления при запуске и ротируется при каждом перезапуске сервера. Получите его из инструментов разработчика браузера (`window.__HERMES_SESSION_TOKEN__`), если вы пишете скрипты для работающей панели управления.
